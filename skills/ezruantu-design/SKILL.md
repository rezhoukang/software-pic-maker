# EZ软图

根据用户项目的真实业务，完成图表设计、可继续编辑的保存和所需格式的输出。客户端负责理解源码和需求，EZ软图 MCP 负责数据校验、自动排版、文件版本和导出。

## 先确认任务与项目

- 区分**源码项目目录**与 **MCP 图表工作目录**：前者由客户端现有文件工具读取，后者通常是 EZ软图的 `data`。`inspect_project` 发现的是图表文件，不是软件源码。
- 通过当前客户端的工具发现机制找到 EZ软图 MCP；工具名称可能带服务前缀。确认具备 `inspect_project`、`read_diagram`、`save_diagram`、`patch_diagram`、`export_project`。未接入或版本过旧时说明需要连接应用“MCP 接入”提供的服务，不假装完成调用，用户未要求设置接入时，不改客户端配置。
- 先 `inspect_project` 定位已有项目和图表，结合当前源码目录、用户指明的系统名称或项目路径选择范围。多个项目无法对应时，只询问这项必要信息。

按真实意图处理“把这个项目的软件设计图全部输出”：

| 当前意图与状态 | 处理方式 |
| --- | --- |
| 明确导出已有图 | 导出目标项目已有图；不补画无关图，不导出其他项目 |
| 要求根据源码/需求设计整套图 | 分析实际项目，确定所需图种，生成或更新后导出 |
| 目录为空，但要求设计图表 | 使用可获得的源码/需求开始设计；不要停在“没有文件可导出” |
| 仅要求某一种图或局部修改 | 只处理该图或明确相关的内容，不扩成整套图重做 |

用户只讨论设计方案时，先讨论，不写文件。用户要求生成、修改或导出时，完成已经授权的工作；不因工具中有写入操作就重复索要确认。

## 生成或完善设计

按需读取项目说明、实体/数据库模型、业务服务、接口入口和相关测试，区分已实现行为与用户要求的目标设计。仅从 UI 名称或数据库表名推断不出的规则，不当作事实写进图中。缺少关键需求时简短询问，同时继续独立可完成的分析。

根据目的选图，读取 [图种选择与建模规则](references/modeling.md) 中相关段落。全套图的数量和图种取决于项目，不强制凑齐八种；较复杂的流程或模块可分成多张语义完整的图。

调用 `get_diagram_schema` 获取当前规则，`list_templates` 只取相关图种作格式参考。字段、枚举、数量限制和引用规则以实时 Schema 与校验结果为准。保留已有业务内容和稳定 ID；新图使用独立、清晰的 ID。不同图对同一角色、实体、服务的含义和命名应一致，允许业务名称与代码标识分别表达。

新图交给自动排版，通常保留空的 `view.positions`；修改现有图时保留已有位置，除非用户要求重新排版。不要用手填坐标或让用户手动拖拽修补自动排版问题。数据保存与修改步骤见 [MCP 工作流](references/mcp-workflows.md)。

## 修改已有内容

先 `read_diagram`，根据实际内容定位修改位置。小修改优先 `patch_diagram`，完整调整使用 `save_diagram`，均携带刚读取的 `revision`。数组索引先核对；必要时用 `test` 检查目标 ID，再进行替换或删除。

保留用户未要求更改的节点、字段、关系和 ID。删除节点时同步处理受影响的引用。文件版本冲突时重新读取并比较：能明确合并的局部修改可基于新版本重试；相同冲突再次发生或无法判断合并意图时停止该文件写入，说明冲突并询问，继续独立可完成的部分。不要循环重试，也不要用旧聚合项目工具绕过版本校验。

## 校验与输出

- 使用 `validate_diagram` 检查结构和引用，必要时 `render_diagram` 核对排版；结构校验不证明业务设计正确。抽查复杂分支、长文本、多参与者、多属性图及用户指出的区域，查看是否有遮挡、裁切、错误箭头或标签压线。
- 校验失败时根据具体错误修正；没有新证据或可行修正时，不机械重复提交同一失败模型，先重新定位问题，仍受阻则说明具体阻碍与已有成果。不会自动把真实模型删减成易通过的示例图。
- 导出范围与格式按用户要求确定。缺少导出格式且无法从上下文确认时，简短询问 PNG、SVG、draw.io、JSON 中的选择；分析、设计和保存可以继续，依赖该选择的最终导出等待答复。不预设“当前图 + PNG”，不沿用上一次任务的格式。
- `export_project` 支持单图、明确路径集合或项目文件夹递归导出。单张实际图表直接生成文件；多张默认文件夹，可指定 ZIP 或两者，至少一种。详细参数与 PNG 能力检查见 [MCP 工作流](references/mcp-workflows.md)。
- 输出返回的实际文件/文件夹路径和格式，简述新建或修改了哪些图、仍有哪些业务假设或缺图。未实际调用并成功写出的文件，不宣称已经导出。

MCP 与桌面通过文件交接，不需要实时控制画布。完成后可提示在桌面刷新并打开相应文件；不要为了图表任务改动业务源码或客户端设置。
