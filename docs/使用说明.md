# EZ软图 0.2.14

面向软件设计与毕业设计的本地绘图工作台。

## 运行

将 ZIP 解压到可写目录，双击 `EZ软图.exe`。Windows 10/11 x64，需要 Microsoft Edge WebView2 Runtime。当前便携包不包含 WebView2。已有运行时的电脑无需安装EZ软图、Go 或 Node.js。

`EZ软图.exe` 是桌面应用；`tuxu-mcp.exe` 是给 MCP 客户端启动的独立程序，直接双击不会出现编辑窗口。

第一次启动会在主目录内创建八张示例文件；如果发现旧版有效恢复数据，会优先迁入“恢复的项目”文件夹。原文件保留。右键主目录或任意文件夹即可新建文件。

## 编辑和文件

- 支持概念 ER 图、表关系图、用例图、流程图、时序图、类图、架构图、功能结构图。
- 点击节点或关系编辑属性；拖动节点调整布局；用“连线”选择起点与终点。
- 用例图在“关系类型”中选择关联、包含 `«include»`、扩展 `«extend»`。包含从基础用例指向被包含用例，扩展从扩展用例指向基础用例。包含/扩展只允许连接两个用例，使用虚线与开放箭头；选中已有连线也能修改类型。
- ER 属性按紧凑程度向实体四周展开，连接靠近实体的一侧，并保留中间的关系通道；多排实体会为上下方属性留足空间。
- 用例自动排版会按参与者和 include/extend 关系分组，将相关用例放在一起；未关联用例集中在下方。用例连线始终是单段直线，允许斜线，不使用折线；遇到阻挡时优先调整自动布局中的用例位置，保留已保存的手动位置。多条箭头会分散落点，尽量减少线段和箭头重叠。include/extend 标签贴近对应连线旋转，保持正向阅读，角度限制在 −85°～85°；画布、PNG、SVG 与 draw.io 共用位置和角度。
- 流程图判断分支从菱形两侧出线；多路正常汇合使用一个自动汇合点和一支入箭头，空间不足时使用不同入口。同侧分支按“早分出的走外侧、晚分出的走内侧”分配入口，避免不必要的交叉和箭头重叠。
- “自动排版”会重新计算当前图表的位置。旧项目保留手动坐标，升级后可点一次自动排版使用新布局。参与者增多时，用例系统边界会随内容扩展。
- 架构图根据现有连接自动分层、排列组件：先按拓扑对齐较长的上下游主干链，再共同分配两端连接点，避免层居中或宽兄弟节点导致无意义弯折。能水平或垂直直连时优先直连，绕行只使用直角且最多转弯两次，尽量减少交叉、重叠和过近的平行线。横向布局优先左进右出，纵向布局优先上进下出；反馈、自连接或障碍使首选方向无法通行时再选择其他侧面。共享组件和密集连接无需额外提供层级标注或坐标，画布与各格式导出使用同一套排版。用例图保留斜直线连接。
- 工具栏右侧“专注画布”可隐藏侧栏和属性面板，扩大绘图区；再次点击退出。拖动空白平移，Ctrl+滚轮缩放，右下角“适应画布”查看全部内容，点击缩放百分比恢复 100%。
- 时序图的参与者保持在同一标题行，消息对齐生命线与执行条。实心箭头为同步调用，虚线开放箭头为返回消息。
- JSON 页面用于粘贴 AI 生成的数据。“校验并应用”会检查结构和引用。未应用的草稿不会保存到项目或自动恢复副本。
- `Ctrl+S` 保存当前文件，`Ctrl+Shift+S` 导出可导入的项目副本；`Ctrl+Z` 撤销，`Ctrl+Shift+Z` 重做。
- 有未保存修改时关闭窗口，会显示应用内确认：选择“取消”返回编辑，选择“直接退出”关闭程序。
- 每个 `.json` 文件保存一张图和布局。顶部“导入项目”兼容旧版 `.tuxu.json`，会导入为独立文件夹及图表文件；“导出项目副本”输出当前图的 `.tuxu.json` 副本。单图 JSON 可粘贴回 JSON 编辑页。
- 支持 SVG、PNG、draw.io 和单图 JSON 导出。SVG 适合清晰缩放，PNG 适合粘贴文档。
- “蓝图 / 论文 / 青绿”位于导出弹窗的“风格”中，应用到本次导出的全部图表，不修改源文件或当前编辑内容。
- draw.io 导出为原生节点与连线，可在 diagrams.net 继续编辑。当前为单向导出，暂不支持导回EZ软图；复杂样式和时序线的后续联动可能需在 draw.io 手动调整。
- 表关系图表达逻辑关联，不会连接数据库或创建外键。

## 文件管理与数据存放

- 左侧树根是“主目录”，对应真实 `data` 文件夹。源码工程内运行任何版本，均使用工程根目录 `data`；程序复制到工程外时，使用程序旁的 `data`。
- 右键文件夹：新增文件夹、新增文件、重命名、删除。主目录本身不能重命名或删除。
- 右键文件：重命名、删除、设计表。“设计表”打开该文件的图形编辑器。新建文件时用分类下拉选择图种；左侧分类筛选只筛文件，目录层级保留。
- 文件树不显示图种图标。顶部用一行路径、文件分类及保存/导出操作替代大标题与装饰徽标。
- 重命名文件或祖先文件夹会同步当前路径，保留未保存的编辑；切换文件会询问是否放弃未保存内容。
- “刷新”重新读取磁盘目录。文件被外部程序修改后，保存会阻止覆盖，编辑器内容保留；可先导出副本再重新打开。
- 删除会将文件或整个文件夹移入 `data/.ezbitu/deleted-*`。如需找回，在对应目录中按 `original.json` 记录的原路径手动恢复。
- 恢复文件为 `data/.ezbitu/recovery.json`，WebView 缓存为 `data/.ezbitu/webview`；这些内部文件不显示在树中。

恢复副本约在编辑后 0.7 秒写入，不代替正式保存，也不包含尚未应用的 JSON 草稿。移动便携程序时，请一起移动 `data`。源码构建需要备份工程根目录的 `data`，而不是 `dist` 中的程序目录。

## MCP

在左下角“MCP 接入”复制配置，加入支持 stdio MCP 的客户端。`tuxu-mcp.exe` 是独立程序，桌面应用关闭时也能使用。软件不内置模型或 API Key：客户端负责理解需求和阅读项目源码，MCP 负责图表数据、校验、自动排版、文件保存和导出。

“复制配置”仅复制 MCP JSON；“复制 Skill”会复制当前 MCP 配置、完整 Skill 和全部建模/操作参考内容，可直接粘贴给 Agent，无需另外查找 Skill 文件。首次使用仍需在客户端完成 MCP 接入，连接后再提出项目和绘图需求。

```json
{
  "mcpServers": {
    "tuxu": {
      "command": "D:\\Tools\\EZ软图\\tuxu-mcp.exe",
      "args": ["--workspace", "D:\\Tools\\EZ软图\\data"]
    }
  }
}
```

工作目录可指定整个 `data` 或其中的某个项目文件夹。所有图表路径均相对该目录，允许子文件夹，不允许越界和链接跳转。空目录不会自动写入示例图。

配套 Skill 位于 `skills/ezruantu-design`，分发时保留整个文件夹。支持加载 `SKILL.md` 的客户端，可按该客户端的安装方式添加；其他具备文件读取与 MCP 工具调用能力的 Agent，可要求它先阅读该目录的 `SKILL.md`，并按需阅读引用文件。Skill 不绑定模型厂商，MCP 需要在客户端另行接入；具体安装目录和调用方式以客户端支持为准。

| 用户意图 | MCP 调用流程 |
| --- | --- |
| “把这个项目已有的软件设计图全部输出” | `inspect_project` 识别项目和图表 → `export_project` 导出项目文件夹 |
| “根据这个项目生成全套设计图” | 客户端阅读实际需求/源码 → 检查已有图 → 读取 Schema 和相关模板 → 编写实际业务数据 → 校验 → 创建文件夹和保存图表 → 导出 |
| “帮我设计一个用例图” | `get_diagram_schema`、`list_templates` → 客户端组织业务模型 → `validate_diagram` → `save_diagram` → `render_diagram` 或 `export_project` |
| “把读者改成注册读者，再加一个访客” | `read_diagram` 获取数据和 revision → `patch_diagram` 原子修改 → 返回新 revision 和备份路径 |

当前提供 13 个工具：

- 项目和编辑：`inspect_project`、`create_folder`、`read_diagram`、`save_diagram`、`patch_diagram`。
- 数据和绘图：`get_diagram_schema`、`list_templates`、`validate_diagram`、`render_diagram`。
- 导出：`export_project`，以及针对内联图表的 `export_diagram`。
- 旧聚合项目 JSON 交换：`save_project`、`open_project`。日常项目建议采用文件夹 + 单图 JSON。

`inspect_project` 返回文件夹、图表路径、名称、类型、revision、校验问题和 `png_available`。未出现的图种仅供参考，不表示每个项目必须包含全部八种图。模板只用于理解格式，不能把模板直接当成用户项目的设计成果。

新建和完整更新使用 `save_diagram`，`diagram` 直接传 JSON 对象。新建文件的父文件夹需先通过 `create_folder` 建立；更新已有文件必须传 `read_diagram` 返回的 revision，防止旧内容覆盖新编辑。

小修改使用 `patch_diagram`，支持 RFC 6902 的 `add`、`replace`、`remove`、`test`，路径采用 JSON Pointer。示例：

```json
{
  "path": "图书系统/用例图.json",
  "revision": "从 read_diagram 获取的版本",
  "operations": [
    { "op": "test", "path": "/model/actors/0/id", "value": "reader" },
    { "op": "replace", "path": "/model/actors/0/name", "value": "注册读者" }
  ]
}
```

一组修改完成后统一校验再保存。操作错误、引用无效或版本冲突时，不会写入部分修改。编辑时保留稳定 ID，删除节点需同步处理关联关系。成功更新前，旧图表数据备份到 `.ezbitu/mcp-backups`，返回值提供备份路径。

整套导出示例：

```json
{
  "path": "图书系统",
  "format": "png",
  "outputs": ["folder", "zip"]
}
```

`format` 支持 `png`、`svg`、`drawio`、`json`。`path` 为项目文件夹，递归包含子目录；省略表示全部工作目录图表，也可用 `paths` 数组指定单张或多张图，两种范围不能同时使用。实际只有一张图时直接生成文件；多张图默认生成文件夹，也可选择 ZIP 或两种结果一起生成，保留目录结构。

输出统一放在工作目录的 `.ezbitu/exports`，返回实际绝对路径，重名时自动加序号。导出结果和备份不会再次进入图表扫描。批量导出先读取并校验全部图表；出错会标明具体文件。PNG 使用本机 Edge 或 Chrome 的隐藏无头进程，支持中文，不需要打开桌面编辑器；没有可用浏览器时会明确报错，可使用 SVG，不会自动下载浏览器。

`export_diagram` 和 `save_project` 的旧文件名参数仍只允许普通文件名。已有同名文件默认拒绝，确需替换时必须显式传 `overwrite: true`。项目文件夹操作应使用新的图表工具。

MCP 不负责实时同步当前画布：文件保存后，在桌面端刷新并打开查看即可。桌面端也有文件版本冲突保护，不会静默覆盖外部修改。真实程序冒烟验证：先 `go build -o build/bin/tuxu-mcp.exe ./cmd/mcp`，再运行 `python scripts/smoke_mcp.py`。

## 第一版范围

本版是可用的 MVP，提供基础图形和规则，并非完整 UML 建模器。尚未提供数据库逆向导入、SQL 导出、PDF 导出、draw.io 导入、复杂时序片段（alt/loop）、活动泳道、协作与云同步。大型复杂图可能需要手动调整布局；文字较长时建议缩短名称或另加说明。

程序为未签名的本地开发版本。兼容性验证仅覆盖当前 Windows x64 开发机；不代表已验证所有 Windows 设备。


## 0.2.4 连线调整

类图、表关系图和架构图的多条关系分配不同连接点，尽量避免独立关系共用同一段主干。类图只使用左、右边框连接，不使用顶部和底部；横向自动排版会围绕连接最多的类，将关联分支按尺寸分配到两侧。两端标题栏存在可通行的共同高度时，会对齐连接点直接连线，避免为几像素的端点差异添加折弯，无需额外提供坐标。表关系图的侧向连接落在标题栏，超过两个侧向连接时分配到顶部。继承使用空心三角形指向父类，依赖使用虚线开放箭头，普通关联和功能树分解线不加箭头。

八种图共用实际边框连接点算法，包含椭圆、菱形、终止节点圆弧和数据库轮廓。关系名及两端基数使用同一场景坐标输出到画布、SVG 和 draw.io；时序调用及返回贴合激活条，嵌套调用支持偏移激活条。

保存并关闭旧窗口后打开新版本；原有手动坐标会保留，需要重新安排节点时点击“自动排版”。手动重叠节点或极密集关系仍可能需要调整位置；draw.io 的原生形状与应用 SVG 形状并非完全相同，导出后请检查排版。


## 0.2.5 拖动与手动排版

左键拖动元素用于调整位置；拖动空白区域用于平移，Ctrl + 滚轮缩放。拖动时折点先在画布中即时跟随，再按后端布局算法持续更新连接点、避障路径和标签，松手后提交位置。一整次拖动只占一个撤销记录，可撤销、重做和保存。

功能结构图按父节点统一计算分支横线；移动某个子节点到不同高度时，兄弟节点仍共用同一条分支横线。子节点移到父节点后方、侧面或公共横线遇到障碍时，改用独立避障连线。组件移到负坐标区域会受到边界限制，避免松手后才突然跳回。

画布编辑与 draw.io 导出保持独立，draw.io 只在导出时执行。保留此附加功能，不以导出格式限制拖动体验。


## 0.2.6 界面整理

分类筛选、文件搜索、顶部保存/导出和配色选项使用 Naive UI 组件。保存、导出按钮统一高度与间距，分类下拉箭头由组件处理；配色使用分段单选，以选中边框表示当前方案，不再额外显示勾号。

删除品牌口号、画布左上信息浮层、顶部重复图种标签和设置面板的重复操作提示。元素/关系数量移动到底部状态栏。文件管理、真实 data 目录、导出格式及配色切换仍可使用。


## 0.2.7 弹窗与表单

新增文件、建立关联、文件夹新建、重命名、删除、帮助、MCP 配置及退出确认统一使用 Naive UI 卡片弹窗。表单使用 Form / FormItem / Input / Select，操作按钮使用 Button；统一中文组件文案。

标题和操作区独立于正文；窗口高度不足时只滚动正文。下拉菜单可在卡片之外展开，菜单本身限制高度并单独滚动，不再滚动整张弹窗。打开下拉菜单后不会因为入场自动聚焦而意外关闭。


## 0.2.8 底部信息整理

去掉左下角版本号和帮助按钮，保留“连接 AI 助手”。操作提示从画布底部移动到右下角状态栏，保存状态和元素/关系统计继续保留；画布底部仅保留缩放与适应画布控件。


## 0.2.9 更名为 EZ软图

应用名称、窗口标题、保存/打开对话框、图表格式标题及发布文件统一为“EZ软图”。现有项目的 data 目录、恢复记录和 `.tuxu.json` 文件继续使用，无需搬移或转换。


## 0.2.10 窗口标题

窗口与浏览器标题仅显示“EZ软图”，移除工作台后缀。


## 0.2.11 滚轮与保存后切换

在画布上直接滚动鼠标滚轮即可放大/缩小，以鼠标所在位置为中心，不再需要按 Ctrl。拖动空白区域仍可平移。删除右下角的保存状态、快捷键和操作提示文字。

切换到其他文件、新建文件或导入项目时，未保存提示提供“取消”“放弃并切换”“保存并切换”。保存完成前禁止其他弹窗操作；保存冲突或失败时保留当前文件及编辑。JSON 模式中，保存并切换会先校验并应用草稿；无效草稿不会写入磁盘，也不会切换。


## 0.2.12 手动调整开关

默认禁止拖动图形节点。工具栏点击“手动调整”后，按钮高亮，才允许手动拖动位置；再次点击关闭。开关本身不修改设计内容，已经保存的位置不会因关闭开关而丢失。

执行自动排版、进入 JSON 模式、切换文件或重新打开应用时，均恢复为禁止拖动。空白平移、直接滚轮缩放、点击节点编辑属性始终可用。自动生成的成图质量仍以无需手动修复为目标，手动调整只是用户主动选择的自定义方式。


## 0.2.13 工具栏与保存状态

“手动调整”移动到工具栏最左侧。文件名旁用文字标签显示“已保存”或“未保存”，替代原先的小圆点；JSON 草稿也计入未保存状态，保存成功后更新标签。
